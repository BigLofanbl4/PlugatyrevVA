#### 1. Базовые привилегии  
```sql
-- Создаем базу данных и пользователей
CREATE DATABASE access_db;

-- Создаем роли writer и reader
CREATE ROLE writer NOLOGIN;
CREATE ROLE reader NOLOGIN;

-- Создаем конкретных пользователей, которые будут входить в эти роли
CREATE USER wl WITH PASSWORD 'password_wl' IN ROLE writer;
CREATE USER rl WITH PASSWORD 'password_rl' IN ROLE reader; -- Обратите внимание, в задании 'nl', я создам 'rl' для ясности

-- Подключаемся к новой базе данных
\c access_db

-- Отзываем все привилегии у роли public в ТЕКУЩЕЙ БД (access_db)
REVOKE ALL ON SCHEMA public FROM PUBLIC;
REVOKE ALL ON DATABASE access_db FROM PUBLIC;

-- Выдаем необходимые привилегии для ролей в ТЕКУЩЕЙ БД
GRANT CONNECT ON DATABASE access_db TO writer, reader;

GRANT USAGE, CREATE ON SCHEMA public TO writer;
GRANT USAGE ON SCHEMA public TO reader;

-- Настраиваем привилегии по умолчанию для будущих таблиц роли writer
ALTER DEFAULT PRIVILEGES FOR ROLE writer IN SCHEMA public
GRANT SELECT ON TABLES TO reader;
```

#### 2. Локализация дат  
```sql
\c postgres
-- Получим номер дня недели (воскресенье = 0, понедельник = 1 ... суббота = 6)
SELECT EXTRACT(DOW FROM CURRENT_DATE) AS day_of_week_number;

-- Изменим локаль сеанса. Например, на немецкую (Германия).
SET lc_time = 'de_DE.UTF-8';
-- Снова получим номер дня недели
SELECT EXTRACT(DOW FROM CURRENT_DATE) AS day_of_week_number_after_locale_change;

-- Проверим, как изменилось отображение названия дня и даты
SELECT TO_CHAR(CURRENT_DATE, 'Day'); -- Название дня
SELECT TO_CHAR(CURRENT_DATE, 'DD.MM.YYYY'); -- Формат даты
```

**Вывод:**  
Параметр `lc_time` влияет на форматирование даты и времени (например, названия дней и месяцев), но **НЕ** влияет на логику вычисления номера дня недели с помощью `EXTRACT(DOW ...)`. Этот номер определяется по фиксированному стандарту (ISO 8601). Поэтому номер дня недели не изменится при смене локали.
